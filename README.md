# ブーン系SS 生成プロンプト生成システム 仕様

本仕様は、このリポジトリのシステム全体を1ファイルで記述する。読者はAIである。本仕様とリポジトリのファイルだけを読めば、システムの動作、データの役割、編集の当て先が確定する。

本仕様の記述は `仕様書修正規約.txt` の規約に従う。本仕様を読むAIは、依頼文の具体例、過去のやりとり、作業メモを参照せずに本仕様だけを根拠にする。

---

## 0. 最初に確定する4つの事実

1. **実装の正は `SS.html` である。** `SS.html` はブラウザで開く1ファイルで、データを取得し、プロンプトを生成し、表示と保存まで行う。`生成py_ユニバーサル版.py` は同じプロンプトをコマンドラインで出力する従属実装である。両者に差がある場合、`SS.html` の挙動を正とする。
2. **生成の入力になるファイルは §2-1 の表に限る。** `評価.txt` と `bwuota/有象無象_結合.txt` は生成の入力にならない。`評価.txt` は生成されたSSを採点する別プロンプトであり、`bwuota/有象無象_結合.txt` は台詞素材の結合テキストである。
3. **生成プロンプトの入力上限は 120,000 字である。** 既定の `maxChar` は 119,000 で、生成物はこの上限の内側に収まる。文章を足す行為は、上限の内側で他のブロックを押し出す。
4. **`キャラテンプレ.txt` は人物の設定本文ではない。** 表形式の人物一覧であり、プロンプトには「汎用キャラクター一覧（サブ・モブ用テンプレ）」として行だけが入る。人物の設定本文は11本のキャラ詳細資料（§2-1）である。

## 1. システムの全体像

### 1-1. 入出力

- 入力：設定（`DEFAULT_PARAMS`、§9）とデータファイル（§2）。
- 出力：1本のプロンプト（テキスト）、生成パターン表示（採用資料・モード・視点固定の状態）、`00_world.md` と `01_characters.md`（採用したキャラ詳細資料を機械分割したもの。内容の追加・要約・言い換えを行わない）。

### 1-2. 実行経路

| 経路 | 実体 | データ取得 |
| --- | --- | --- |
| ブラウザ（正） | `SS.html` | `raw.githubusercontent.com` から毎回取得。取得失敗時は前回取得した内容を用い、画面に警告を出す。ローカルファイルとテキスト直接入力も選べる（§11-2） |
| コマンドライン（従属） | `生成py_ユニバーサル版.py` | リポジトリ直下の同名ファイルを読む。`output/` に `genprompt.txt`、`00_world.md`、`01_characters.md` を書く |

### 1-3. 生成の流れ

1. 乱数でマルコフ次数を決める（`markovOrder = 0` のとき 1〜5）。
2. `続き.txt` の文字数から末尾指示（tail）と視点抑止（suppressHero）を決める（§10-4）。
3. 資料オンリーモードを決める（`shuryoOnlyMode = 0` のとき `-1 / 2 / 3` から抽選）。
4. 内側リトライを最大 `maxRetry` 回行う。試行が失敗する条件は、上限超過、固定視点と採用資料の矛盾、採用キャラ資料の合計文字数が `minCharMaterialChars` に届かないこと（`-1 / 3` のみ）。
5. 外側リトライを最大 `maxOuterRetry` 回行う。外側1回につき内側の生成を2回行い、長い方を採用する。
6. モード2のときだけ、tail を完成プロンプトの末尾に付ける。`-1 / 3` では tail を上限計算に含めてブロックの1つとして置く。

## 3. 用語

- **キャラ詳細資料**：`二次創作.txt` など11本の人物設定本文。人物ブロック単位で構成される。
- **キャラテンプレ**：`キャラテンプレ.txt` の表。人物の設定本文を持たず、一覧提示の材料になる。
- **汎用キャラクター一覧**：キャラテンプレの行から抽選してプロンプトに置く表。サブ・モブの人物を資料外で作らせないための提示である。
- **資料オンリーモード**：`-1`（通常）、`2`（モード2）、`3`（モード3）。`1` は欠番。
- **キャラ優先度**：11資料29名を毎回シャッフルした順序。人物単位で順序を決め、資料txt単位でプロンプトへ入れる（§7-1）。
- **前半マルコフ／後半マルコフ**：mode `2 / 3` で2本置かれるマルコフ文。前半の素材は `SS.txt`・キャラ詳細資料11本・`共通.txt` の連結、後半の素材は `マルコフ.txt` 単体（§6-1）。
- **骨格カード**：冒頭／終盤の骨格辞書から1枚抽選した物語機能の組。
- **冒頭フロー行／終盤フロー行**：`冒頭は、〜` `終盤は、〜` の1行と、その直後に置く指示文。
- **題材断片**：`マルコフ.txt` から作る1行と、その注記。
- **視点行**：`今回の視点は[ AA 名前 ]です`。直後に改行のみで `一人称視点の形式で書くこと` を連結することがある。
- **文字数行**：`文字数は X~Y 文字`。

## 4. 資料オンリーモード

### 4-1. モードの決まり方

- `shuryoOnlyMode = -1`：通常。キャラ優先度を使う。
- `shuryoOnlyMode = 2`：モード2。キャラ詳細資料を読ませず、AIオリジナル設定で書かせる。
- `shuryoOnlyMode = 3`：モード3。キャラ優先度を使い、前半マルコフに全資料と `SS.txt` を含める。
- `shuryoOnlyMode = 0`：`-1 / 2 / 3` から毎回抽選する。
- `shuryoOnlyMode = 1`：欠番。指定された場合は `-1` として扱う。

### 4-2. 差分表

| 要素 | mode `-1` | mode `2` | mode `3` |
| --- | --- | --- | --- |
| `資料.txt` | 先頭 | 2番目 | 先頭 |
| `SS.txt` ブロック | 入る | 先頭に入る | 入らない（前半マルコフの素材のみ） |
| キャラ詳細資料 | 優先度順に入る | 入らない | 優先度順に入る |
| `禁止.txt` | 入る | 入らない | 入る |
| `共通.txt` ブロック | 入る | 入らない | 入る |
| キャラクター間の関係ルール | 入る（保護ブロック） | 入らない | 入る（保護ブロック） |
| 汎用キャラクター一覧 | 採用資料の人物を除いて抽選 | 詳細資料を持つ人物の固定枠＋抽選枠 | 採用資料の人物を除いて抽選 |
| マルコフ本数 | 1本（`マルコフ.txt`） | 2本（前半・後半） | 2本（前半・後半） |
| マルコフ行数の上限 | `markovLinesMax` | `markovLinesMaxShuryo` | `markovLinesMaxShuryo` |
| 2人視点の無関係宣言 | 出る | 出ない | 出る |
| 資料未提示人物の宣言 | 出る | 出ない | 出る |
| グループ横断の既知接点 | 出る | 出ない | 出る |
| 採用資料の合計文字数下限の検査 | ある | ない | ある |
| `00_world.md` / `01_characters.md` | 採用資料から作る | 作らない | 採用資料から作る |

### 4-3. mode `-1`（通常）

キャラ優先度で採用したキャラ詳細資料群をプロンプト先頭に置き、`資料.txt`、`SS.txt`、`禁止.txt`、`共通.txt` を続ける。マルコフは `マルコフ.txt` 単体から1本だけ作り、直後に `↑` と題材断片の注記を置く。

### 4-4. mode `2`（モード2）

キャラ詳細資料を一切プロンプトに入れない。人物の設定はAIが本文用に組み立てる。プロンプトは `SS.txt` と `資料.txt` で始まり、`禁止.txt` と `共通.txt` のブロックを持たず、関係ルールを持たない。

- 視点人物は内蔵の人物リストから抽選する。特殊視点の候補はキャラテンプレから作る。`doubleHeroRate` による2人視点、`specialHeroRate` による特殊視点は他のモードと同じく働く。
- 2人視点でも無関係宣言を置かない。視点行は `今回の視点は[ …… ]です` で終わる。
- 汎用キャラクター一覧は詳細資料を持つ人物を固定枠として常に載せ、そのうえで抽選枠を加える（§7-2）。
- マルコフは2本。前半は `SS.txt`・キャラ詳細資料11本・`共通.txt` の連結から、後半は `マルコフ.txt` 単体から作る。各本の直後に `---` と題材断片の注記を置く。

### 4-5. mode `3`（モード3）

キャラ優先度を使う点は mode `-1` と同じ。`SS.txt` をブロックとして置かず、前半マルコフの素材に `SS.txt` とキャラ詳細資料11本と `共通.txt` を含める。マルコフは2本。

### 4-6. モード共通の骨格

どのモードも、末尾の固定位置に「視点行（と一人称指示） → 文字数行」を置く。トーンブロック、冒頭フロー行、終盤フロー行、題材断片は設定で有効な限り全モードに入る。

## 5. プロンプトのブロック構成

### 5-1. mode `-1 / 3` の順序

1. 採用キャラ詳細資料群（資料txt単位。txt内の人物ブロックは毎回シャッフル）
2. キャラクター間の関係ルール（保護ブロック）
3. `資料.txt`（内容があるとき）
4. `SS.txt`（mode `-1` のみ）
5. `禁止.txt`
6. `共通.txt`
7. 主要AA制約行（`主要AAのキャラのみを使用し、モブを用意する場合も12-2の選出順序に従う`）
8. 前半マルコフ（mode `3`）／`マルコフ.txt` 単体（mode `-1`）
9. 後半マルコフ（mode `3` のみ）
10. `続き.txt`（内容があるとき）
11. `最後.txt`
12. 汎用キャラクター一覧（`最後.txt` の直後）
13. 冒頭フロー行＋指示文
14. 終盤フロー行＋指示文
15. 題材断片＋注記
16. トーンブロック
17. 末尾追加テキスト（`customTailText`）
18. 視点行（＋一人称指示）
19. 文字数行

### 5-2. mode `2` の順序

1. `SS.txt`
2. `資料.txt`（内容があるとき）
3. 主要AA制約行
4. 前半マルコフ
5. 後半マルコフ
6. `続き.txt`（内容があるとき）
7. `最後.txt`
8. 汎用キャラクター一覧（`最後.txt` の直後）
9. 冒頭フロー行＋指示文
10. 終盤フロー行＋指示文
11. 題材断片＋注記
12. トーンブロック
13. 末尾追加テキスト（`customTailText`）
14. 視点行（＋一人称指示）
15. 文字数行

### 5-3. 保護ブロック

関係ルールと汎用キャラクター一覧は、上限の空きに関わらず載せる。収まらない場合は採用キャラ詳細資料を優先度の末尾から外して確保する。固定視点の所属資料を外す必要が出た場合は、その試行を失敗としてリトライする。

### 5-4. ブロックランダム順モード

`shuffleBlocksMode = 1` のとき、本文ブロックを丸ごとシャッフルする。視点行から文字数行までの末尾固定ブロックはシャッフルの対象外で、常に最後にこの順で置く。

### 5-5. 区切りと注記

- 前半・後半マルコフの直後：`---` と題材断片の注記。
- `-1` のマルコフ直後：`↑` と題材断片の注記。
- 題材断片の直後：`↑` と題材断片の注記（主題や教訓として書かせない指示を含む）。
- 冒頭／終盤フロー行の直後：骨格カード由来なら骨格強制の指示、マルコフ由来なら意図補完の指示。

## 6. マルコフ

### 6-1. 素材と本数

| 対象 | 素材 |
| --- | --- |
| mode `-1` のマルコフ | `マルコフ.txt` 単体 |
| mode `2 / 3` の前半マルコフ | `SS.txt` ＋ キャラ詳細資料11本 ＋ `共通.txt` を改行で連結したもの。素材の範囲は採用資料の選出結果に依存せず、常に全資料を対象にする |
| mode `2 / 3` の後半マルコフ | `マルコフ.txt` 単体 |
| 冒頭／終盤の代替行、題材断片 | `マルコフ.txt` 単体 |

### 6-2. 行数・次数・揺らぎ

- 本数あたりの行数は1行から上限まで。上限は `-1` が `markovLinesMax`、`2 / 3` が `markovLinesMaxShuryo`（いずれも上限1000）。
- 次数は `markovOrder`（0のとき1〜5を抽選）。
- `markovFluctuation = 1` のとき、文ごとに「次数」と「次数−1」の連鎖を等確率で使い分ける。
- 1文の長さは `markovSentenceMinChars` 以上 `markovSentenceMaxChars` 以下。
- 素材はマークダウンを除去してから連鎖を作る。骨格辞書と `冒頭スロット.txt` / `終盤スロット.txt` の語彙は除去しない。

### 6-3. 1行マルコフ

冒頭フロー行、終盤フロー行、題材断片は、`マルコフ.txt` から作る1行を使う。1行マルコフは次数4固定、揺らぎなしで作る。1行が得られない場合は固定の題材断片文に切り替える。

### 6-4. 骨格カードとスロット

`useSkeletonEngine = 1` のとき、冒頭／終盤フロー行は `skeletonRate`（既定50%）の確率で骨格辞書から作る。骨格辞書は `冒頭スロット.txt` / `終盤スロット.txt` の中身から自動判別する。`#AXIS` と `#TEXT` を含む場合は骨格辞書として読み、含まない場合はマルコフ代替に回す。

骨格辞書の軸値には文章化テンプレートを書ける。部品は `+` で区切り、`#軸名` は軸値、`=文字列` は固定文字列、`スロット名@#軸名` は他の軸の値で語彙を絞り込む指定を表す。スロット名が `・` で終わるときは、その軸の値をスロット名に連結した語彙プールを使う。`#KEY` 行は意味的重複の判定に使う軸を指定する。直近の生成履歴で出過ぎた軸は重みを下げ、直近カードと物語機能が近い組合せは引き直す。履歴はブラウザの localStorage に保存する。

## 7. キャラクターの扱い

### 7-1. キャラ優先度（mode `-1 / 3`）

11資料29名を人物単位でシャッフルし、上から順にその人物の所属txtを採用する。採用はtxt単位で、既に採用したtxtに属する人物は飛ばす。人物ブロックはtxt内で毎回シャッフルする。視点を固定した場合も優先度の順序は変えない。固定人物の所属txtが採用されていない試行は失敗としてリトライする。

採用は上限に達するまで続く。関係ルールと汎用キャラクター一覧の分を先に確保し、収まらない場合は末尾の資料から外す。

### 7-2. 汎用キャラクター一覧

- **mode `2`**：キャラ詳細資料を持つ人物（11資料29名）の行を、提示数に関わらず常に載せる（固定枠）。表に行がない人物は一覧に載らない。固定枠の並び順は生成のたびにシャッフルし、視点人物の行だけを一覧の先頭に置く。固定枠の後ろに、`charTemplateMin`〜`charTemplateMax`（既定12〜40）の枠だけ残りの行から抽選して加える。行の照合は表の行名で行い、代表AAでは照合しない。
- **mode `-1 / 3`**：採用したキャラ詳細資料に属する人物の行を除き、残りから `charTemplateMin`〜`charTemplateMax` の枠だけ抽選する。視点人物の行は必ず含める。
- 表の書式は §10-1。表が取得できない場合は一覧を置かない。

### 7-3. 視点

- 通常の視点人物は、キャラ詳細資料の採用範囲（`-1 / 3`）または内蔵の人物リスト（`2`）から抽選する。
- `doubleHeroRate` の確率で2人視点。`-1 / 3` では、別資料の2人かつ既知接点がない組合せに限り、`AA 名前（組織）と AA 名前（組織）は、互いに一切の面識・接点を持たない完全な無関係（他人）である。` を視点行の直後に置く。mode `2` はこの文を置かない。
- `specialHeroRate` の確率で特殊視点。候補はキャラテンプレから作る（取得できない場合のみ内蔵リスト）。
- `heroMode = 0` は視点なし、`1` は必ず視点、`-1` は `noHeroRate` により視点なしを混ぜる。
- `firstPersonRate` の確率で、視点行の直後に空行を挟まず `一人称視点の形式で書くこと` を連結する。ヒットした回は視点なしを選ばず視点行を出す。
- `fixedHero` は視点人物を1名に固定する。`group:資料ID` の形式では、その資料に属する人物から1名を生成ごとに抽選する。固定時は視点モード・視点なしレート・特殊視点・2人視点を無視する。

### 7-4. 資料未提示人物の宣言（mode `-1 / 3`）

採用した資料の本文に名前が登場するのに、その人物の資料が採用されていない場合、関係ルールの末尾に名前を列挙し、設定の創作と登場の制限を宣言する。視点人物は列挙から除く。

### 7-5. グループ横断の既知接点（mode `-1 / 3`）

関係ルールは、採用資料の組に応じて組織間の無関係を宣言する。資料に接点が明記されている組には、その記載を優先して宣言する。`when` を持つ接点は、指定された資料も同時に採用されている回だけ宣言する。

## 8. 文字数上限

### 8-1. 上限

- 生成プロンプトの入力上限は 120,000 字。
- 既定の `maxChar` は 119,000。`maxChar` がプロンプト全体の上限として働く。
- 本文の目標文字数（`charCountMin` / `charCountMax`）は上限とは別で、プロンプトに `文字数は X~Y 文字` として書かれる。

### 8-2. 上限の内側で決まるもの

- キャラ詳細資料の採用数（§7-1）。
- マルコフの行数（`markovLinesMax` / `markovLinesMaxShuryo`。実際の行数は残り文字数でも止まる）。
- 汎用キャラクター一覧の抽選枠（1行あたりの表の長さに依存する）。
- 冒頭／終盤フロー行と題材断片の長さ（`マルコフ.txt` 由来の1行は残り文字数で切られる）。

### 8-3. 超過時の挙動

- ブロックを置いた結果が上限を超えると、その試行は失敗し、リトライに回る。リトライではマルコフ行数の上限を縮める。
- 保護ブロック（関係ルール・汎用キャラクター一覧）は上限に空きがなくても載せる。収まらない場合は採用キャラ詳細資料を末尾から外す。
- 題材断片は残り文字数が尽きても載せるため、その分だけ上限を繰り上げる。

### 8-4. 文章量と挙動

上限に達した状態で文章を足すと、その分だけ他のブロックがプロンプトから落ちる。表や指示文を足す行為は、キャラ詳細資料の採用数、マルコフの行数、抽選枠のいずれかを減らす。修正の評価は、増えた文字数ではなく、生成されるプロンプトの内容とモードごとの差で行う。

## 10. データファイルの書式

### 10-1. キャラテンプレ.txt

表形式。`|` で区切った行を1人物として読み、`代表AA` を含む行を見出し、`| --- |` 形式の行を区切りとして扱う。1列目が人物名、2列目が代表AA。人物名は `（` 以降を除いた部分で照合する。一覧の読み取りは `|` の単純分割であり、代表AAに `|` を含む行は列が崩れる。代表AAは `|` を含まない表記で書く。

### 10-2. 冒頭スロット.txt / 終盤スロット.txt

`#AXIS` と `#TEXT` を含む場合は骨格辞書、含まない場合はマルコフ素材として扱う。骨格辞書の記法は §6-4。

### 10-3. トーン.txt

1行1トーン名。空行は無視する。内容がない場合は内蔵のトーン名を使う。

### 10-4. 続き.txt

文字数で末尾指示が決まる。

| 文字数 | 挙動 |
| --- | --- |
| 1000以下 | 末尾指示を置かない |
| 1000超〜30000未満 | 「続きを書きなさい」系の指示を1つ抽選して置く |
| 30000以上 | 最大のピンチと未回収要素の回収を命じる指示を置き、視点抑止を有効にする |

### 10-5. SS.txt / 共通.txt / 禁止.txt / 最後.txt / 資料.txt

いずれも自由記述。ブロックとしてプロンプトに置く。`SS.txt` は mode `3` でブロックとして置かず、前半マルコフの素材に含める。

### 10-6. キャラ詳細資料

人物ごとのブロックで構成する。人物ブロックの区切りは、代表AAで始まる行。資料の内部は人物ブロック単位でシャッフルして提示する。グループ概要・世界設定などの人物以外の見出し以降は末尾に残す。

## 11. 編集と反映

### 11-1. 反映経路

- `SS.html` は生成のたびに GitHub の raw から各ファイルを取得する。リポジトリ上でデータファイルを編集して保存すると、次の生成から反映される。
- 取得に失敗したスロットは、前回取得した内容を使い、画面に警告を出す。内容がないスロットはスキップする。

### 11-2. スロットの取得方法

| 方法 | 挙動 |
| --- | --- |
| GitHub | raw URL から取得（既定） |
| ローカルファイル | 選択したファイルを読む。読めない場合はメモリ上の内容を使う |
| テキスト直接入力 | 入力した内容を使う |
| 使用しない | スロットを空にする |

`資料.txt`、`禁止.txt`、`続き.txt` は既定で「使用しない」。他は既定で GitHub。

### 11-3. 変更の当て先

| 変更したいもの | 当て先 |
| --- | --- |
| プロンプトの生成規則、モードの差、ブロック構成、抽選、上限の扱い | `SS.html` の生成エンジン。`生成py_ユニバーサル版.py` の同じ箇所にも同じ規則を入れる |
| 画面、設定項目、取得方法、保存、表示 | `SS.html` のみ |
| 人物設定、本文の規則、トーン名、禁止事項、骨格辞書 | 該当するデータファイル |

`SS.html` の生成エンジンは `<script>` 内の `NovelGen` にある。モード分岐は次の2関数である。

- `buildContentsWithPriority`：mode `-1 / 3` の本体。
- `buildContents`：mode `2` の本体。

mode `2` と `3` で共有する規則（前半マルコフの素材、汎用キャラクター一覧の固定枠、視点の注記の有無）は、両関数の対応箇所を同時に読む。

### 11-4. 編集後の確認

実データで生成し、次の項目を確認する。

1. `-1 / 2 / 3` のそれぞれで生成が成功し、プロンプトが `maxChar` の内側に収まる。
2. mode `2` にキャラ詳細資料の本文、関係ルール、無関係宣言、`禁止.txt`、`共通.txt` のブロックが入らない。
3. mode `-1 / 3` にキャラ詳細資料が優先度順で入り、関係ルールと汎用キャラクター一覧が最後の位置に入る。
4. 前半マルコフに `共通.txt` の内容が素材として効いている。
5. 汎用キャラクター一覧の固定枠29行が欠けず、抽選枠が `charTemplateMin`〜`charTemplateMax` に収まり、行の重複がない。
6. 視点行、一人称指示、文字数行の3つが末尾の固定位置にある。
7. `生成py_ユニバーサル版.py` が同じプロンプトを出力する。
