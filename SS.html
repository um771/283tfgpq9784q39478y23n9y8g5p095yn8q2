❓ 使い方・仕組み

◆ 使い方

  • このページをブラウザで開いて、「🚀 ワンクリック生成＆コピー」を押すだけ。
  • 生成されたプロンプトは自動でクリップボードにコピーされ、下の欄にも表示されます。そのままAI（ChatGPT等）に貼り付けて小説を生成してください。
  • 実行のたびにキャラ資料の優先度（および採用範囲）・視点・テーマ・トーン・文字数がランダムに変わります。
  • 上級パラメータの「視点キャラ固定」で29名のいずれかを選ぶと、今回の視点は[ AA 名前 ]です がそのキャラに確定します（全モード共通）。固定時は視点モード・視点なしレート・特殊視点・2人視点を無視して必ず単独視点で出します。

◆ データはどこから来るの？（GitHub参照）

  • デフォルトでは GitHub リポジトリ um771/283tfgpq9784q39478y23n9y8g5p095yn8q2 の main ブランチにある SS.txt / 二次創作.txt / 超加速.txt / ラボ組.txt / 学校組.txt / ホスト組.txt / ツン.txt / 渡辺さん.txt / ハイン.txt / でぃ.txt / マルコフ.txt / 冒頭.txt / 終盤.txt / 冒頭スロット.txt / 終盤スロット.txt / トーン.txt / 最後.txt を raw.githubusercontent.com から取得します。
  • マルコフ.txt や 最後.txt、各キャラ資料をリポジトリ上で編集して保存 → このページで生成 すれば、最新版が反映されます（毎回最新を取得）。
  • 資料オンリーモード（-1／3）では、9資料のキャラ計29名に対して優先度をランダム設定し、上から所属する資料（二次創作・超加速・ラボ組・学校組・ホスト組・ツン・渡辺さん・ハイン・でぃ）のtxtを追加していき、文字数上限に収まる順番までをプロンプト先頭へ追加します。視点キャラ固定時は固定キャラの所属txtが採用されていることを確認し、不採用ならリトライします（例：ブーン固定なのに二次創作.txt不採用、という破綻は起きません。優先度の順序自体は改変しません）。
  • 一人称視点指定（全モード共通）：一人称視点指定レート（％・既定50）の確率で、末尾固定ブロックの 今回の視点は[ ～ ]です の直後に空行を挟まず 一人称視点の形式で書くこと を追加します（トーンブロックの後・文字数は～文字 の前の固定位置）。ヒットした回は視点なしレート・視点モード0を無視して必ず視点行を出します（続き.txtによる視点抑止中を除く）。資料オンリーモードの設定値（-1／2／3およびランダム）に関係なく全モードで動作します。
  • 冒頭／終盤のスロット辞書合成（既定ON）：冒頭スロット.txt / 終盤スロット.txt は意味スロット辞書です。品詞・意味役割ごとに分類された語彙プール（スロット）と、スロットの並び順と接続を固定した文型（フレーム）を直積して「冒頭は、〜ことになる。」「終盤は、〜ことになる。」の1文を組み立てます。フレームが助詞と接続を保持するため、出力は文法的に正しい日本語になります。語彙行の @タグ でフレーム側から候補を絞り込み、^グループ=値 の排他指定で意味的に衝突する組み合わせを引き直します。パターン数は文型数と各スロットの語彙数の積で決まるため、#SLOT に語彙を1行足すだけで掛け算に増えます。辞書はリポジトリ上で編集するだけで反映されます。
  • 冒頭.txt / 終盤.txt の扱い：この2ファイルは、スロット辞書の語彙を採集する素材であり、マルコフ合成のコーパスです。スロット合成時の既存行そのまま採用率（％）は既定0で、0のときは行をそのまま1行として使うことはありません。スロット合成の結果がこの2ファイルの行と一致した場合、一致を理由に引き直さずそのまま採用します。
  • フロー指示文：スロット辞書で組み立てた1行の直後には「↑ これが冒頭の流れ。この冒頭で仕込んだ独自の要素をセットアップとして必ず後半で回収しろ。」（終盤は「↑ これが終盤の流れ。この終盤の着地を、前半で既に置いた要素の回収によって実現しろ。」）を置きます。マルコフ連鎖で組み立てた1行の直後には、文が破綻していても意図を補完して強引に解釈させる指示を含めた文を置きます。冒頭／終盤のスロット辞書合成をOFFにした場合、辞書が取得できない場合、試行回数内に合格文が出ない場合は、マルコフ連鎖で1行を組み立てます。
  • ブロックランダム順モード（デフォルトOFF）をONにすると、プロンプトの各ブロック（採用キャラ資料群・関係ルール・SS.txt・共通.txt・各マルコフ＋区切り・最後.txt・キャラテンプレ・冒頭／終盤／テーマ／トーン等）を毎回ランダムな順番に並べ替えます。「視点提示 → 文字数指定」の2つだけはシャッフルされず、常に最後の固定位置（一人称指定行は視点提示の一部として同じく固定）です。「マルコフ文＋これは資料です」等のペアは順序のまま維持されます。
  • 採用した各キャラ資料txtの内部では、そのtxtの代表AAで始まる人物ブロックを毎回ランダムな順に並べ替えます（★欲の位置はファイルごとに違うため使いません）。グループ概要・世界設定など人物以外の見出し以降は末尾に残します。
  • 旧来の統合資料 他の人.txt は旧Python版との互換用に残っていますが、SS.htmlでは参照しません。
  • 特殊視点（今回の視点は[ ラベル：AA 名前 ]です）の候補キャラは キャラテンプレ.txt の表から「代表AA＋全角スペース＋キャラ名（（…）以降を除去）」の形式で毎回組み立てます。テンプレに行を追加・修正すれば候補へ自動反映されます（テンプレ未取得時のみ内蔵リストを使用）。採用したキャラ資料に登場するキャラは資料側の名前を優先します（例：超加速採用時はテンプレ名「杉浦ロマネスク」ではなく資料名「ロマネスク」になります）。AA欄に | を含む場合は \| と書いてください（書いた通りの文字が候補に使われます）。
  • 取得に失敗した場合は「前回取得した内容」を自動で使い、警告を表示します。
  • リポジトリを変えたい場合は「⚙ 設定」のリポジトリ欄を書き換えるか、各ファイルのURLを直接編集してください。

◆ ローカルファイルを使う場合

  • 設定の各ファイル行で「参照元」をローカルファイルに切り替え、📁 ボタンで選択します。
  • Chrome / Edge なら選択したファイルを記憶し、毎回最新の内容を読み込み直します（ファイルを編集→生成、が反映される）。
  • 他のブラウザでは選択内容をキャッシュします（ファイル変更時は再選択）。
  • 「テキスト直接入力」にすると、画面内の欄に内容を貼り付けて使えます。

◆ 保存機能（改稿システム用）

  • genprompt.txt … AIへ渡したプロンプト全文（元pyの write_genprompt 相当）。
  • 00_world.md / 01_characters.md … 採用された資料を機械分割したもの（元pyの write_split_files 相当）。
  • 生成後に各ボタンで保存できます。

◆ エラーが出るとき

  • GitHub取得に失敗する場合：①ネットワーク確認 ②リポジトリ名・ブランチ名の確認 ③参照元を「ローカルファイル」に変更。
  • ブラウザの制限で取得できない環境（まれ）では、このHTMLをGitHubリポジトリに index.html として置き、 GitHub Pages（Settings → Pages → Deploy from branch）で公開すれば確実に動きます。
  • クリップボードコピーが効かない環境では、下の欄から手動コピーしてください。
  • 設定はこのブラウザに自動保存されます。「すべて初期状態に戻す」でリセットできます。

  • strip_markdown・マルコフ統計・分割ファイルの基本動作をテストで確認済みです。
